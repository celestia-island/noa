# ワークスペース分離の設計

## 概要

ワークスペースは、エージェントと人間のための分離された作業コンテキストを提供します。各ワークスペースは独立した状態（ヘッドスナップショット、エージェントログ）を持ちながら、基盤となるオブジェクトストアを共有します。

## ワークスペース構造

```rust
pub struct Workspace {
    pub name: String,
    pub head: SnapshotId,     // 現在のスナップショット
    pub base: SnapshotId,     // 親ワークスペースからのフォークポイント
    pub agent_id: Option<String>,  // 関連付けられたエージェント
    pub created_at: u64,
    pub updated_at: u64,
}
```

## ワークスペースのライフサイクル

```mermaid
flowchart LR
    A["create"] --> B["switch"]
    B --> C["(agent writes + snapshots)"]
    C --> D["merge"]
    D --> E["delete"]
```

### 作成

```bash
noa workspace create feature-1
```

1. 現在のワークスペースのヘッドスナップショットを読み取り → `base`となる
2. 新しいワークスペース: `head = base` (現在の状態を継承)
3. エージェントログファイルを作成: `agent-logs/feature-1.log`
4. WorkspaceStoreに登録

### 切り替え

```bash
noa workspace switch feature-1
```

1. ワークスペースの存在を確認
2. ワークスペース名を`.noa/HEAD`に書き込み
3. 前のワークスペースを`.noa/ORIG_HEAD`に保存

### マージ

```bash
noa workspace merge feature-1
```

1. 3方向マージ: base → ours (現在) vs theirs (feature-1)
2. 両方を親とするマージスナップショットを作成
3. 現在のワークスペースのヘッドを更新

### 削除

```bash
noa workspace delete feature-1
```

1. アクティブなワークスペースでないことを確認
2. ストアからワークスペースエントリを削除
3. エージェントログファイルを削除
4. オブジェクトは保持される (共有、コンテンツアドレス型)

## HEADファイル

`.noa/HEAD`にはアクティブなワークスペース名が含まれます:

```
feature-1
```

`.noa/ORIG_HEAD`には前のワークスペースが含まれます (元に戻す用):

```
default
```

## ワークスペースストア

ワークスペースはredbに格納されます:

```
テーブル: workspaces
  キー:   "feature-1" (ワークスペース名を&strとして)
  値:     msgpack(Workspace) を &[u8]として
```

ヘッドの更新にはCAS (compare-and-swap)を使用します:

```rust
async fn update_head(&self, name: &str, expected: &SnapshotId, new: &SnapshotId) -> Result<()>
```

これにより、複数のプロセスが同じワークスペースを同時に更新しようとした場合の更新ロストを防ぎます。

## Gitブランチとの比較

| 観点 | noaワークスペース | Gitブランチ |
|--------|---------------|------------|
| ストレージ | redbテーブルエントリ | refファイル (`.git/refs/heads/`) |
| 分離 | 独自のエージェントログファイル | 共有インデックス + ワーキングツリー |
| 切り替え | アトミックなHEAD書き込み | ワーキングツリーのチェックアウト (ファイルI/O) |
| 作成 | O(1) — メタデータのみ | O(1) — 軽量 |
| 削除 | ストアから削除 | refを削除、オプションでプルーニング |
| エージェントバインディング | オプションのagent_idフィールド | 同等の機能なし |
| ベース追跡 | 明示的なbaseフィールド | 暗黙的 (マージベース) |

## SVNブランチとの比較

| 観点 | noaワークスペース | SVNブランチ |
|--------|---------------|------------|
| ストレージ | KVエントリ | 完全なディレクトリコピー |
| 作成 | O(1) メタデータ | O(n) ファイルコピー |
| 分離 | 論理的 (共有オブジェクト) | 物理的 (別ディレクトリ) |
| マージ追跡 | 親DAG | svn:mergeinfoプロパティ |

## 設計の根拠

### ブランチではなくワークスペースを選んだ理由

1. **エージェント識別**: ワークスペースは帰属表示用の`agent_id`フィールドを持つ
2. **エージェントログの分離**: 各ワークスペースに専用のログファイル
3. **ワーキングツリーなし**: noaはチェックアウトを維持しない — スナップショットのみ
4. **明示的なベース**: `base`フィールドにより高速なマージベース計算が可能

### ワーキングツリーのチェックアウトがない理由

Gitブランチはワーキングツリーのチェックアウトが必要です（切り替えられたファイルごとのファイルI/O）。noaワークスペースはポインタのみを切り替えます — エージェントログとスナップショット参照のみです。これはリポジトリサイズに関係なくO(1)です。

ファイルの具現化（チェックアウト）は、エージェントが実際のファイルを読み書きする必要があるときに、スナップショットのツリーを信頼できるソースとして別途行われます。
