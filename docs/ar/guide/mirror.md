# المرآة والتدفق العكسي

يستوعب نظام المرآة فرع master لكل مستودع وجميع الـ tags ورؤوس PR النشطة من مضيفين خارجيين (GitHub وغيره) إلى noa؛ ثم تدفع قناة التدفق العكسي حالة noa عودةً إلى المصدر — مشكِّلةً الصورة الانتقالية «noa هو المرجعية + GitHub مرآة»، بينما يواصل farm/CNB الجلب من GitHub دون أي تغيير.

## وظائف المرآة (MirrorJob)

```json
{
  "name": "noa",
  "remote_url": "https://github.com/celestia-island/noa.git",
  "github_slug": "celestia-island/noa",
  "branches": ["master"],
  "tags": true,
  "pr_heads": true,
  "backflow": true,
  "canary_push": true,
  "enabled": true
}
```

| الحقل | الوصف |
|---|---|
| `name` | `^[a-z0-9][a-z0-9-]{0,63}$`؛ وهو أيضًا اسم مجلد النسخة المؤقتة، واسم المستودع في الفهرس، ومقطع مسار الاستنساخ |
| `remote_url` | يُسمح فقط بـ `https://` / `file://`؛ وتُرفض بيانات الاعتماد المضمّنة في الرابط (`@`, `?`) |
| `github_slug` | تحقق شكل `owner/repo`؛ يُستخدم في مسار Git Data API (جلب tags / رؤوس PR) ومسبار canary؛ دفع back-flow يمر عبر `remote_url` |
| `branches` | فرع واحد على الأقل؛ تُرفض `tags`/`tags/*` و `pr/*` (تعارض مع نطاق PR) وأي صيغ غير صالحة لمساحات العمل المشتقة |
| `tags` | تعكس جميع الـ tags |
| `pr_heads` | تعكس رؤوس PR النشطة (`refs/pull/<N>/head` → `mirror/{job}/pr/<N>`) |
| `backflow` | تدفع حالة النسخة المؤقتة عودةً إلى المصدر مع كل موجة (التفاصيل أدناه) |
| `canary_push` | تدفع مرجع مسبار واحد للتحقق من اتجاه الكتابة |
| `enabled` | عند الإيقاف يتخطى المجدول هذه الوظيفة |

عمليات CRUD: `POST/GET /api/v1/mirror/jobs`، و`DELETE /api/v1/mirror/jobs/{name}`، و`POST /api/v1/mirror/run` (تشغيل يدوي، بجسم `{"job":"<name>"}`).

## القناتان

- **قناة git**: نسخة مؤقتة bare + `git fetch` — الـ tags ورؤوس PR ودفعات التدفق العكسي كلها تمر عبرها.
- **قناة API**: عندما تتعطل نقلية git (عائلة اهتزاز الشبكة)، تتحول تلقائيًا إلى استيراد blob بـ blob عبر Git Data API؛ ويُتحقق من SHA لكل blob (المطابقة لا تتدهور بتغير القناة).

التبديل يتم بمقياس الموجة الواحدة: فشل `ensure_scratch` → تأخذ هذه الموجة قناة API → الإصلاح الذاتي يحذف النسخة المؤقتة نصف المعطوبة والموجة التالية تعيد الاستنساخ. دفعات التدفق العكسي تجري فقط ما دامت قناة git متاحة (قناة API لا تستطيع دفع المراجع).

## رؤوس PR

مع `pr_heads: true` تجلب كل موجة إضافةً لذلك `refs/pull/<N>/head` وتستوردها كـ `mirror/{job}/pr/<N>` مع مساحة عمل تحمل الاسم نفسه. نطاق PR ونطاق الفروع (الفروع بصيغة `pr/<x>`) متنافيان ويُرفض الاثنان معًا عند upsert.

## التدفق العكسي

```text
scratch local refs ──atomic push──▶ origin
  +refs/heads/*:refs/heads/*
  +refs/tags/*:refs/tags/*
  +refs/pull-heads/*:refs/noa/pr/*     (only when pull-heads exist in the scratch)
```

- **بيانات الاعتماد**: الرمز الذي يُحل من `token_env` (الافتراضي `NOA_MIRROR_GH_TOKEN`) يضمَّن في رابط push أحادي الاستخدام بصيغة `x-access-token:<token>`؛ والرمز لا يهبط أبدًا في إعدادات النسخة المؤقتة.
- **دلالات الإجبار**: بعد الانقلاب تصبح noa هي سلطة الكتابة وتتقارب مراجع المصدر على النسخة المؤقتة. الحذف غير المتناظر (حذف على جانب noa لا يحذف المرجع في جانب المصدر) قيد معروف.
- **دلالات الفشل**: التدفق العكسي الفاشل يعلّم الموجة FAILED — فهذه قناة حرجة للقبول ويجب أن تبقى ظاهرة بوضوح.
- **جسر النطاقات**: يرفض GitHub الدفعات إلى `refs/pull/*`، لذا تهبط رؤوس PR في `refs/noa/pr/<N>`.

## مسبار canary

مع `canary_push: true` تدفع كل موجة مرجع مسبار `noa-mirror-canary` إلى المصدر (وهو commit أول فرع مكرر)، أولًا عبر نقلية git ثم تتحول إلى Git Data API عند الفشل — للتحقق المستمر من بيانات اعتماد اتجاه الكتابة ومن الاتصال. المسبار الفاشل يجعل الموجة تفشل بصوت عالٍ.

## التحقق من المطابقة

كل commit مستورد يُدقَّق بندًا بندًا: مجموعة المسارات ونوع المدخل وblob OID (`git_blob_oid` يطابق git) يجب أن تطابق تمامًا؛ وأي اختلاف يُفشل ذلك البند ويهبط في تفاصيل أخطاء الموجة. التدفق العكسي يعتمد على هذا الثابت — كائنات noa تقابل كائنات git واحدًا لواحد، فلا حاجة لأي طبقة تحويل عند الدفع.

## تنظيف المراجع المتقادمة (reconcile)

مجموعات الـ tags ورؤوس PR في المستوى الأعلى تشكّل مجموعة reconcile: المراجع التي لم تعد تظهر في المستوى الأعلى تُنظَّف من noa (النطاقان `mirror/{job}/tags/` و `mirror/{job}/pr/`). ودفع tags في التدفق العكسي يتبع المستوى الأعلى كذلك (حذف على جانب noa لا يحذف جانب المصدر — عدم تناظر معروف).

## الجدولة

مع `NOA_MIRROR_ENABLED=1` يشغّل المجدول جولة كاملة على جميع الوظائف المفعلة كل 900 ثانية؛ و`POST /mirror/run` يشغّل جولة يدويًا. تفاصيل الموجة (القناة، نتائج البنود، حالة backflow/canary) موجودة في `GET /api/v1/mirror/jobs` تحت `last_detail` / `last_lane`.
