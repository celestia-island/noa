# بروتوكول git-http

يقدّم `/git/{repo}/*` البروتوكول الذكي عبر HTTP: مسار القراءة يشغّل `git upload-pack --stateless-rpc` مباشرة، ومسار الكتابة (منذ W2a2) يشغّل `git receive-pack --stateless-rpc` مباشرة — دون غلاف `git-http-backend` CGI، وبذلك تبقى المفاوضة على البروتوكول ومتغيرات البيئة وأشكال الأخطاء تحت السيطرة الكاملة.

## نقاط النهاية

| الطريقة | المسار | الغرض |
|---|---|---|
| GET | `/git/{repo}/info/refs?service=git-upload-pack` | إعلان clone/fetch |
| POST | `/git/{repo}/git-upload-pack` | التفاوض على الحزمة |
| GET | `/git/{repo}/info/refs?service=git-receive-pack` | إعلان push |
| POST | `/git/{repo}/git-receive-pack` | استقبال الدفعات |

يجب أن يكون `{repo}` اسم وظيفة مرآة — فجسم الخدمة هو النسخة المؤقتة bare الخاصة بتلك الوظيفة (`NOA_MIRROR_SCRATCH_DIR/{repo}.git`). المستودع غير الموجود يعيد 404.

## تفاصيل السلوك

- **التفاوض على البروتوكول**: تمرَّر رأس `Git-Protocol` القادم من العميل إلى العملية الفرعية كما هي — المقصود بـ v2 هنا **النسخة الأعلى من البروتوكول السلكي لـ git** (gitprotocol-v2، معيار git نفسه وليس رقم إصدار noa)؛ والفراغ يعني v0 افتراضيًا. هذا بالضبط سبب استبدال التشغيل المباشر لـ git-http-backend — غلاف CGI يسقط ذلك الرأس على مسار POST، فينخفض الصمت إلى v0 ويكسر عمليات clone.
- **تمهيد الإعلان**: pkt-line الخاصة بـ `# service=` (تُحسب رأس الطول ديناميكيًا من اسم الخدمة) + flush؛ واستجابات RPC بلا تمهيد.
- **Content-Type**: `application/x-git-{upload,receive}-pack[-advertisement]` مع تمييز صارم بينها.
- **جسم الطلب**: جسم POST يُكتب مباشرة إلى stdin للعملية الفرعية؛ وتفك `Content-Encoding: gzip` تلقائيًا (تُرفض نسبة فك الضغط > 1000:1 — حماية من قنابل الضغط؛ حدود 50 MiB للطلب / 200 MiB بعد فك الضغط).
- **المهلة**: للحوار كله 60 ثانية على الساعة؛ وعند انتهائها تُقتل العملية الفرعية (kill_on_drop يمنع بقاء حائزي الأقفال أيتامًا).
- **التزامن**: إشارة عد (semaphore) على مستوى المسار تحدد الحوارات الجارية بالتوازي (سقف الذاكرة 4×50 MiB).
- **بيئة العملية الفرعية**: بعد `env_clear` يبقى فقط `PATH` + `GIT_PROTOCOL` — تسرب البيئة مستحيل في زمن التصريف.

## دلالات push

تهبط الدفعات في المراجع المحلية للنسخة المؤقتة؛ و**نجاح receive-pack يُطلق فورًا موجة الاستيراد الخاصة بتلك الوظيفة** (دون انتظار المجدول) — يظهر المحتوى المدفوع فورًا على واجهة API (المراجع/اللقطات/مساحات العمل). ثم تقوم الموجة بما يلي:

1. تستورد المراجع المتقدمة للنسخة المؤقتة إلى نظام المراجع في noa (اللقطات / مساحات العمل)؛
2. عند تفعيل `backflow` تدفع الحالة عودةً إلى المصدر.

لذلك لا تحتاج الدفعات إلى أي hooks خاصة — القنوات الثلاث (القراءة، الاستقبال، التدفق العكسي) تتشارك نسخة مؤقتة واحدة والحلقة المغلقة تتقارب تلقائيًا. الدفعات تتطلب هوية مصادَقة؛ بلا بيانات اعتماد 401 + تحدٍّ من نوع `Basic`، ودور reader يحصل على 403.

## الحدود المعروفة

- الدفعات لا توفر دلالات حذف (حذف على جانب noa لا يُنقل إلى المصدر — عدم تناظر معروف).
- بروتوكول dumb HTTP (ملفات `/info/refs` الخام) غير مُخدوم.
- رؤوس PR تهبط في `refs/noa/pr/<N>` عند التدفق العكسي (GitHub يرفض الدفعات إلى `refs/pull/*`).
- مصدر دفع الـ back-flow هو كائنات git في الـ scratch — **الـ commits الأصلية في noa** (لقطات مساحات عمل خالصة لم تمر عبر الـ scratch) خارج نطاق الـ back-flow حتى يوفر مُسلسل لقطة → كائنات git (انظر [البنية](./architecture.md)).
