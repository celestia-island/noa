# الدمج والتعارض

دمج noa بنية من طبقتين — «التعاود على مستوى الشجرة + الأوراق على مستوى الأسطر»: المجلدات تتعاود مستوى فمستوى، وتعارضات الملفات تحاول أولًا دمجًا ثلاثي الاتجاه على مستوى الأسطر (diff3)، ثم تتراجع إلى تعارضات مهيكلة عند الفشل.

## الدمج الثلاثي على مستوى الأسطر (W2④)

عند تعديل الجانبين على الملف نفسه، يُجرى أولًا فحص diff3 بالسلف المشترك كأساس:

- **المناطق التي لمسها جانب واحد فقط**: تؤخذ من ذلك الجانب مباشرة — التعديلات غير المتداخلة تُدمج تلقائيًا ولم تعد تنتج تعارضات لكل blob على حدة؛
- **المناطق المتداخلة أو المتلاصقة** (اتساقًا مع git؛ والفراغ الصفري يُعد أيضًا تعارضًا): تُولَّد كتل علامات تعارض على طراز git (`<<<<<<< ours` / `=======` / `>>>>>>> theirs`)، ويُحفظ التعارض المهيكل ليُحل من جهة اللوحة؛
- **التطابق التام أو جانب لم يلمسه**: يأخذه المسار السريع مباشرة.

```rust
use libnoa::merge::line_merge::{merge_lines, LineMerge};

match merge_lines(base, ours, theirs) {
    LineMerge::Clean(merged) => { /* auto-resolved */ }
    LineMerge::Conflict { merged, ours, theirs, base } => { /* structured conflict */ }
}
```

## إعادة التسمية بالمحتوى المطابق تمامًا (W2④ slice 2)

عندما يكون أحد الجانبين «إعادة تسمية خالصة» (حُذف المسار القديم وظهر المحتوى نفسه من الـ blob حرفيًا في المسار الجديد) بينما **عدّل الجانب الآخر المسار القديم**، يُطبَّق التعديل تلقائيًا على **المسار الجديد** — وسيناريو إعادة التسمية + التعديل الكلاسيكي لم يعد ينتج تعارض «حذف مقابل تعديل».

الحالات غير المعلنة (تتراجع تحفظًا إلى تعارضات مهيكلة):

- إعادة التسمية غيّرت المحتوى أيضًا (إعادة تسمية بحمولة)؛
- أعاد الجانبان التسمية إلى هدفين مختلفين؛
- مسار الهدف لُمس من الجانب الآخر (تصادم)؛
- إعادة تسمية مقابل حذف (إعادة التسمية تحمل محتوى الأساس وتبقى في المسار الجديد — دلالات git المراعية لإعادة التسمية).

الاستدلالات التقاربية (كشف إعادة التسمية خارج التطابق التام) شريحة لاحقة.

## دلالات التبسيط عند الفشل

عندما يتعذر الدمج على مستوى الأسطر (blob مفقود / تالف / ثنائي / يحتوي CR منفردًا)، يتراجع ذلك الملف إلى تعارض مهيكل لكل blob على حدة — الملفات **لا** تُسقَط أبدًا بصمت، ولا يعيد النظام أبدًا 500. وشكل الفيكسچر للفراغ التام على الأجانب الثلاثة (التخزين يُجسّد المعرفات المفقودة كـ blobs فارغة) يتبسّط بالطريقة نفسها.

## تدفق دمج PR

`POST /api/v1/repos/{name}/prs/{number}/merge`:

1. دمج ثلاثي للقطات (base = أساس PR، ours = مساحة العمل الهدف، theirs = رأس PR)؛
2. لا تعارض → تهبط الشجرة تلقائيًا + تتقدم المراجع؛
3. تعارض → 409 + قائمة تعارضات (المسار + معرفات blobs ours/theirs/base)؛ وتحل اللوحة كل تعارض عبر `ConflictResolution::{Ours, Theirs}`.

## التوافق مع git

نتائج الدمج تحقق جبر كائنات git: الشجرة المحلولة يمكن كتابتها مباشرة عودةً إلى النسخة المؤقتة وتدفقها عكسيًا (دفع تدفق عكسي + تحقق من المطابقة، صفر تحويل في المسار كله).
