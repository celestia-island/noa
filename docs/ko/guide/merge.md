# 머지와 충돌

noa의 머지는 2계층 구조입니다 — "트리 수준 재귀 + 라인 단위 잎": 디렉터리는
계층별로 재귀하고, 파일 수준 충돌은 먼저 라인 단위 3방향 머지(diff3)를
시도하며, 실패 시 구조화된 충돌로 폴백합니다.

## 라인 단위 3방향 머지 (W2④)

양쪽이 같은 파일을 수정한 경우 공통 조상을 base로 diff3 스캔이 먼저
실행됩니다:

- **한쪽만 건드린 영역**: 그쪽 값을 그대로 취합니다 — 겹치지 않는 편집은
  자동으로 머지되며 더 이상 전체 blob 충돌을 만들지 않습니다;
- **겹치거나 인접한 영역**(git과 일치; 간격 0도 충돌로 셈): git 스타일 충돌
  마커 블록(`<<<<<<< ours` / `=======` / `>>>>>>> theirs`)을 생성하고,
  구조화된 충돌을 패널 측 해결용으로 보존합니다;
- **완전히 동일하거나 한쪽이 건드리지 않음**: 지름길 경로가 그대로
  처리합니다.

```rust
use libnoa::merge::line_merge::{merge_lines, LineMerge};

match merge_lines(base, ours, theirs) {
    LineMerge::Clean(merged) => { /* auto-resolved */ }
    LineMerge::Conflict { merged, ours, theirs, base } => { /* structured conflict */ }
}
```

## 정확한 내용 기반 리네임 (W2④ 슬라이스 2)

한쪽이 "순수한 리네임"(오래된 경로가 삭제되고 같은 blob 내용이 그대로 새
경로에 나타남)이고 다른 쪽이 **오래된 경로를 수정**한 경우, 수정은 **새
경로에** 자동 적용됩니다 — 고전적인 rename+edit 시나리오가 더 이상
"삭제 vs 수정" 충돌을 만들지 않습니다.

미선언 사례(보수적으로 구조화된 충돌로 폴백):

- 리네임이 내용도 변경한 경우 (payload 리네임);
- 양쪽이 서로 다른 대상으로 리네임;
- 다른 쪽이 대상 경로를 건드린 경우 (충돌);
- 리네임 vs 삭제(리네임은 base 내용을 실은 채 새 경로에서 살아남습니다 —
  git의 rename 인지 시맨틱스).

유사도 휴리스틱(정확 일치를 넘어선 리네임 감지)은 이후 슬라이스입니다.

## 폴백 시맨틱스

라인 단위 머지를 사용할 수 없을 때(blob 누락/손상/바이너리/홀로 남은 CR
포함), 해당 파일은 구조화된 전체 blob 충돌로 폴백합니다 — 파일이 조용히
버려지는 일은 **절대** 없고, 500도 발생하지 않습니다. 세 방향이 모두
빈(empty) fixture 형태(스토리지가 누락된 id를 빈 blob으로 구체화)도 같은
방식으로 저하합니다.

## PR 머지 흐름

`POST /api/v1/repos/{name}/prs/{number}/merge`:

1. 3방향 스냅샷 머지 (base = PR base, ours = 대상 워크스페이스,
   theirs = PR head);
2. 충돌 없음 → 트리가 자동 반영 + ref 전진;
3. 충돌 → 409 + 충돌 목록(path + ours/theirs/base blob id); 패널이
   `ConflictResolution::{Ours, Theirs}` 기준으로 해결합니다.

## git 호환성

머지 결과는 git 객체 대수를 만족합니다: 해결된 트리는 스크래치에 곧바로
기록되고 백플로우될 수 있습니다(백플로우 푸시 + 충실도 검증, 전 과정에서
변환 0).
