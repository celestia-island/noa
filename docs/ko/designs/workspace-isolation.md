# 워크스페이스 격리 설계

## 개요

워크스페이스는 에이전트와 인간을 위한 격리된 작업 컨텍스트를 제공합니다.
각 워크스페이스는 기반 객체 저장소를 공유하면서 독립적인 상태(헤드 스냅샷, 에이전트 로그)를 가집니다.

## 워크스페이스 구조

```rust
pub struct Workspace {
    pub name: String,
    pub head: SnapshotId,     // 현재 스냅샷
    pub base: SnapshotId,     // 부모 워크스페이스에서 분기한 지점
    pub agent_id: Option<String>,  // 연결된 에이전트
    pub created_at: u64,
    pub updated_at: u64,
}
```

## 워크스페이스 생명 주기

```mermaid
flowchart LR
    A["생성"] --> B["전환"]
    B --> C["(에이전트 쓰기 + 스냅샷)"]
    C --> D["병합"]
    D --> E["삭제"]
```

### 생성

```bash
noa workspace create feature-1
```

1. 현재 워크스페이스의 헤드 스냅샷 읽기 → `base`가 됨
2. 새 워크스페이스: `head = base` (현재 상태 상속)
3. 에이전트 로그 파일 생성: `agent-logs/feature-1.log`
4. WorkspaceStore에 등록

### 전환

```bash
noa workspace switch feature-1
```

1. 워크스페이스 존재 확인
2. 워크스페이스 이름을 `.noa/HEAD`에 기록
3. 이전 워크스페이스를 `.noa/ORIG_HEAD`에 저장

### 병합

```bash
noa workspace merge feature-1
```

1. 삼방향 병합: base → ours(현재) vs theirs(feature-1)
2. 양쪽을 부모로 하는 병합 스냅샷 생성
3. 현재 워크스페이스 헤드 업데이트

### 삭제

```bash
noa workspace delete feature-1
```

1. 활성 워크스페이스가 아님을 확인
2. 저장소에서 워크스페이스 항목 제거
3. 에이전트 로그 파일 삭제
4. 객체는 유지됨 (공유, 콘텐츠 주소 지정)

## HEAD 파일

`.noa/HEAD`는 활성 워크스페이스 이름을 포함합니다:

```
feature-1
```

`.noa/ORIG_HEAD`는 이전 워크스페이스를 포함합니다 (실행 취소용):

```
default
```

## 워크스페이스 저장소

워크스페이스는 redb에 저장됩니다:

```
테이블: workspaces
  키:   "feature-1" (&str로서의 워크스페이스 이름)
  값:   msgpack(Workspace) (&[u8]로서)
```

헤드 업데이트는 CAS(compare-and-swap)를 사용합니다:

```rust
async fn update_head(&self, name: &str, expected: &SnapshotId, new: &SnapshotId) -> Result<()>
```

이는 여러 프로세스가 동일한 워크스페이스를 동시에 업데이트하려고 할 때 소실 업데이트를 방지합니다.

## Git 브랜치와의 비교

| 측면 | noa 워크스페이스 | Git 브랜치 |
|--------|---------------|------------|
| 저장 | redb 테이블 항목 | ref 파일 (`.git/refs/heads/`) |
| 격리 | 자체 에이전트 로그 파일 | 공유 인덱스 + 작업 트리 |
| 전환 | 원자적 HEAD 쓰기 | 작업 트리 체크아웃 (파일 I/O) |
| 생성 | O(1) — 메타데이터만 | O(1) — 경량 |
| 삭제 | 저장소에서 제거 | ref 삭제, 선택적으로 정리 |
| 에이전트 바인딩 | 선택적 agent_id 필드 | 해당 없음 |
| 베이스 추적 | 명시적 base 필드 | 암시적 (병합 베이스) |

## SVN 브랜치와의 비교

| 측면 | noa 워크스페이스 | SVN 브랜치 |
|--------|---------------|------------|
| 저장 | KV 항목 | 전체 디렉터리 복사 |
| 생성 | O(1) 메타데이터 | O(n) 파일 복사 |
| 격리 | 논리적 (객체 공유) | 물리적 (별도 디렉터리) |
| 병합 추적 | 부모 DAG | svn:mergeinfo 속성 |

## 설계 근거

### 브랜치 대신 워크스페이스를 사용하는 이유?

1. **에이전트 신원**: 워크스페이스는 귀속을 위한 `agent_id` 필드를 가집니다
2. **에이전트 로그 격리**: 각 워크스페이스는 전용 로그 파일을 가집니다
3. **작업 트리 없음**: noa는 체크아웃을 유지하지 않습니다 — 스냅샷만 유지
4. **명시적 베이스**: `base` 필드는 빠른 병합 베이스 계산을 가능하게 합니다

### 작업 트리 체크아웃이 없는 이유?

Git 브랜치는 작업 트리 체크아웃이 필요합니다 (전환된 모든 파일에 대한 파일 I/O).
noa 워크스페이스는 포인터만 전환합니다 — 에이전트 로그와 스냅샷 참조만.
이는 저장소 크기에 관계없이 O(1)입니다.

파일 구체화(체크아웃)는 에이전트가 실제 파일을 읽거나 써야 할 때 별도로 발생하며, 스냅샷의 트리를 신뢰 소스로 사용합니다.
