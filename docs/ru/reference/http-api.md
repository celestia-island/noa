# Справочник HTTP API

Базовый URL: `http://<host>:<port>/api/v1`. Все эндпоинты требуют bearer-аутентификации
(`Authorization: Bearer <token>`); неаутентифицированные запросы получают 401 + challenge `Basic`.
Применение ролей: запросы на запись от reader получают 403; не-GET на `/users` — только admin.

Ошибки имеют единую форму `{"error": "..."}`; пагинация встроенная (`?limit=` 1..=1000,
`?offset=`).

## repos — каталог репозиториев

| Метод | Путь | Описание |
|---|---|---|
| GET | `/repos` | список каталога |
| POST | `/repos` | регистрация (требуется `name`, та же форма, что и имена задач зеркалирования) |
| GET | `/repos/{name}` | одна запись |
| DELETE | `/repos/{name}` | удаление (409, пока жива задача зеркалирования или существуют открытые PR) |
| GET | `/repos/{name}/prs` | список PR в рамках репозитория |
| POST/GET | `/repos/{name}/runs` | записи запусков CI (см. [Записи запусков CI](../guide/ci-runs.md)) |

## prs — pull-запросы

| Метод | Путь | Описание |
|---|---|---|
| GET | `/prs?state=&base=&repo=&limit=&offset=` | глобальный список (`state` ∈ open/closed/merged) |
| POST | `/prs` | создание (title, repo, base, head и т.д.) |
| GET | `/prs/{number}` | одна запись |
| POST | `/prs/{number}/merge` | слияние (squash/fast-forward; конфликты — 409 со списком конфликтов) |

Вариант в рамках репозитория: `GET /repos/{name}/prs` — репозиторий определяется путём;
противоречащий фильтр `?repo=` возвращает 400.

## users — пользователи и роли (admin)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/users` | список (admin) |
| POST | `/users` | создание/обновление (то же имя = смена токена или роли; `created_us` сохраняется) |
| GET | `/users/{name}` | одна запись (admin) |
| DELETE | `/users/{name}` | удаление (admin, необратимо) |

Роли: `admin` (всё) / `operator` (чтение-запись) / `reader` (только чтение). Поля и валидация:
см. [Права доступа и пользователи](../guide/rbac.md).

## mirror — задачи зеркалирования

| Метод | Путь | Описание |
|---|---|---|
| GET | `/mirror/jobs` | список всех задач (включая `last_status` / `last_lane` / `last_detail`) |
| POST | `/mirror/jobs` | создание/обновление (валидация с тем же именем полностью сбрасывает задачу) |
| DELETE | `/mirror/jobs/{name}` | удаление задачи |
| POST | `/mirror/run` | ручной запуск (тело `{"job":"<name>"}`, 202 асинхронно) |

Поля, валидация и семантика каналов: см. [Зеркалирование и обратный поток](../guide/mirror.md).

## git-http — смарт-протокол

`/git/{repo}/*`: clone/fetch (upload-pack) и push (receive-pack). Аутентификация, детали
поведения и границы: см. [Протокол git-http](../guide/git-http.md).

## Общие соглашения

- `limit` по умолчанию 50 и не выше 1000 на всех списочных эндпоинтах (`limit=0` → 400);
- параметры пагинации **встроены** в строку запроса (без вложенного объекта-обёртки);
- поля, назначаемые сервером (такие как `number`, `started_us`), выставляются сервером;
  переданные клиентом значения перезаписываются;
- ошибки не раскрывают внутренние детали (постоянная форма `internal server error`); детали
  уходят в серверные логи.
