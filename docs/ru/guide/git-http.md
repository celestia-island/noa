# Протокол git-http

`/git/{repo}/*` обслуживает смарт-протокол HTTP: путь чтения напрямую вызывает
`git upload-pack --stateless-rpc`, а путь записи (начиная с W2a2) напрямую вызывает
`git receive-pack --stateless-rpc` — без CGI-обёртки `git-http-backend`, поэтому согласование
протокола, переменные окружения и формы ошибок полностью под контролем.

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/git/{repo}/info/refs?service=git-upload-pack` | анонс clone/fetch |
| POST | `/git/{repo}/git-upload-pack` | согласование pack |
| GET | `/git/{repo}/info/refs?service=git-receive-pack` | анонс push |
| POST | `/git/{repo}/git-receive-pack` | приём push |

`{repo}` должен быть именем задачи зеркалирования — обслуживающее тело это голый scratch-клон
задачи (`NOA_MIRROR_SCRATCH_DIR/{repo}.git`). Несуществующий репозиторий возвращает 404.

## Детали поведения

- **Согласование протокола**: заголовок `Git-Protocol` клиента передаётся дочернему процессу
  (v2 включается по требованию; пустое значение — v0 по умолчанию). Именно поэтому реализация с
  прямым вызовом заменила git-http-backend — CGI-обёртка теряет этот заголовок на POST-пути,
  молча откатываясь к v0 и ломая клонирование.
- **Преамбула анонса**: pkt-line `# service=` (заголовок длины вычисляется динамически из имени
  сервиса) + flush; ответы RPC не содержат преамбулы.
- **Content-Type**: `application/x-git-{upload,receive}-pack[-advertisement]` строго различаются.
- **Тело запроса**: тело POST пишется напрямую в stdin дочернего процесса;
  `Content-Encoding: gzip` распаковывается автоматически (коэффициент распаковки > 1000:1
  отклоняется — защита от бомб; лимиты 50 МиБ на запрос / 200 МиБ на распакованное).
- **Таймаут**: на весь обмен отводится 60 секунд реального времени; при таймауте дочерний процесс
  уничтожается (kill_on_drop предотвращает осиротевших держателей блокировок).
- **Параллелизм**: маршрутный семафор ограничивает число одновременных git-обменов (потолок памяти
  4×50 МиБ).
- **Окружение дочернего процесса**: после `env_clear` остаются только `PATH` + `GIT_PROTOCOL` —
  утечка окружения исключена на уровне компиляции.

## Семантика push

Push попадает в локальные ссылки scratch; затем волна зеркалирования:

1. импортирует продвинутые ссылки scratch в систему ссылок noa (снимки/рабочие пространства);
2. при включённом `backflow` отправляет состояние обратно в origin.

Поэтому push не требует специальных хуков — три пути (чтение, приём, обратный поток) делят один
scratch, и замкнутый контур сходится автоматически. Push требует аутентифицированной идентичности;
без учётных данных — 401 + challenge `Basic`, роль reader — 403.

## Известные границы

- Push не несёт семантики удаления (удаление на стороне noa не распространяется в origin —
  известная асимметрия).
- dumb HTTP (сырые файлы `/info/refs`) не обслуживается.
- PR-головки при обратном потоке попадают в `refs/noa/pr/<N>` (GitHub отклоняет push в
  `refs/pull/*`).
