# Записи запусков CI (runs API)

В noa встроено хранилище записей запусков CI: один «конвейер проверок, выполненных против
некоторого репозитория на некотором head» — это один run. Это источник данных для канала
`CI_BACKEND=noa` представления CI DevOps-панели chest.

## Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/v1/repos/{name}/runs` | записывает один запуск (роль на запись) |
| GET | `/api/v1/repos/{name}/runs?limit=&offset=` | список, сначала новые |

- `{name}` должен существовать в каталоге (иначе 404);
- `number` назначается сервером на каждый репозиторий (атомарно: сканирование и запись происходят
  в одной транзакции записи, поэтому параллельные записи никогда не перезаписывают номера друг
  друга);
- Валидация: `head_sha` — 40 hex-символов; `status` ∈
  `queued | running | success | failure | cancelled`; `kind` — 1..=64 символа; `actor` — 1..=200;
  `log_ref` / `summary` ≤ 2000.

## Запись запуска

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{
    "head_sha": "<40-hex>",
    "kind": "basic-check",
    "status": "success",
    "actor": "farm-runner-1",
    "log_ref": "https://ci.example.com/logs/123"
  }' \
  http://127.0.0.1:3016/api/v1/repos/noa/runs
```

Ответ (201): сервер заполняет `repo`, `number` и `started_us` (если клиент их не передал).

## Запрос

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:3016/api/v1/repos/noa/runs?limit=10&offset=0"
```

Возвращаемые строки выглядят так:

```json
{
  "repo": "noa",
  "number": 1,
  "head_sha": "…",
  "kind": "basic-check",
  "status": "success",
  "actor": "farm-runner-1",
  "started_us": 1794049465562618
}
```

## Проектные границы

- **Логи не хранятся в noa**: записи несут непрозрачный указатель `log_ref` на хранилище логов
  конвейера диспетчеризации;
- **Содержимое строки ограничено** (см. валидацию) — не позволяя аутентифицированным писателям
  раздувать размер строк;
- **Хранилище**: таблица `runs` в redb с ключом `{repo}#{number:020}` (лексикографический порядок =
  хронологический порядок внутри репозитория).

## Интеграция с chest

Обработчик `ci_ops` в chest читает переменную окружения `CI_BACKEND`:

- `github` (по умолчанию): канал v1 GitHub Actions, поведение идентично историческим версиям;
- `noa`: читает runs API noa, на который указывают `NOA_API_BASE` + `NOA_API_TOKEN`, нормализуя
  строки в ту же форму панели, что и строки GitHub (`kind`→name, `number`→run_number,
  `started_us`→RFC3339 `created_at`, конечные статусы отображаются в conclusion); список наблюдения
  берётся из `CI_NOA_REPOS` (имена каталогов из одного сегмента), а если не задано — из последнего
  сегмента `CI_GITHUB_REPOS`.

`ci.config.get` панели сообщает поле `backend`; `configured` учитывает backend — чистое
noa-развёртывание (без токена GitHub) считается подключённым, пока полный триплет настроек noa
задан.
